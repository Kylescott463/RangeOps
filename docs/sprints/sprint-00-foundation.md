# Sprint 0 — Product and Architecture Foundation

## Sprint details

- **Duration:** One week
- **Developer:** Solo
- **Status:** In progress
- **Sprint goal:** Establish an agreed, testable product direction and engineering
  foundation before application code is written.

## Committed stories

| ID | Story | Acceptance criteria |
| --- | --- | --- |
| FND-001 | Define product scope | Users, MVP capabilities, rules, workflows, non-goals, and success criteria are documented |
| FND-002 | Select architecture | Project boundaries, dependencies, data model, readiness design, and cross-cutting decisions are documented |
| FND-003 | Establish delivery process | Prioritized backlog, sprint sequence, definition of done, and Git conventions are documented |

## Sprint tasks

- [x] Install and verify .NET 10 SDK.
- [x] Install and verify Docker Desktop and Docker Compose.
- [x] Install required VS Code extensions.
- [x] Create the local Git repository on `main`.
- [x] Configure the GitHub `origin` remote.
- [x] Record the product vision and MVP boundary.
- [x] Record the readiness and maintenance policies.
- [x] Select the layered modular-monolith architecture.
- [x] Draft the core data model and project boundaries.
- [x] Create and prioritize the release backlog.
- [x] Define story and sprint completion standards.
- [x] Review these decisions with the project owner.
- [x] Create the initial documentation commit.
- [ ] Push the initial commit to GitHub.

## Exit criteria

Sprint 0 is complete when:

1. The project owner accepts or amends the documented scope and decisions.
2. All Sprint 0 documents are committed on `main`.
3. The initial commit is visible in the GitHub repository.
4. Sprint 1 can begin without unresolved product or architecture blockers.

## Review checklist

Before accepting the sprint, confirm:

- The four user roles are appropriate.
- The inspection rule should compare against the mission start date.
- The ticket workflow requires independent verification.
- All assigned mission assets are considered required.
- Overlapping mission windows should prevent duplicate asset assignment.
- Cloud deployment and a custom frontend remain outside the MVP.
- The seven-sprint implementation sequence is realistic for the desired pace.
